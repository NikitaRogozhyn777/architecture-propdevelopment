# Проверочный лист по безопасности данных для PropDevelopment

## 1. Классификация данных по категориям

| Категория данных       | Примеры данных в PropDevelopment                                                                 |
|------------------------|--------------------------------------------------------------------------------------------------|
| **Публичные данные**   | - Описание жилых комплексов (без персональных данных)                                           |
|                        | - Условия бронирования и покупки недвижимости                                                   |
|                        | - Общая информация о сервисах (без доступа к ЛК)                                                |
| **Внутренние данные**  | - Логи и метрики работы сервисов                                                                |
|                        | - Внутренние отчёты по продажам                                                                 |
|                        | - Техническая документация API                                                                  |
|                        | - Данные о доступных объектах недвижимости (без клиентских данных)                              |
| **Конфиденциальные данные** | - Персональные данные клиентов (ФИО, контакты)                                              |
|                        | - Данные о сделках (номера договоров, суммы)                                                    |
|                        | - Данные собственников (платежи ЖКХ, доступ к Умному дому)                                     |
|                        | - Результаты онлайн-осмотров недвижимости                                                       |
| **Секретные данные**   | - Ключи доступа к API партнёров                                                                 |
|                        | - Финансовые реквизиты клиентов (банковские данные)                                             |
|                        | - Данные интеграции с госорганами                                                               |
|                        | - Административные доступы к системам                                                           |


## 2. Риски для каждой категории данных

| Категория данных       | Риски                                                                                           |
|------------------------|-------------------------------------------------------------------------------------------------|
| **Публичные данные**   | - Искажение данных (например, некорректная информация о жилых комплексах)                      |
|                        | - Обесценивание данных (устаревшие данные снижают доверие клиентов)                            |
| **Внутренние данные**  | - Утечка данных (например, доступ к внутренним отчётам конкурентами)                           |
|                        | - Потеря данных (отсутствие бэкапов технической документации)                                  |
| **Конфиденциальные данные** | - Утечка данных (например, доступ к персональным данным клиентов злоумышленниками или партнёрами) |
|                        | - Искажение данных (ошибки в CRM, из-за которых клиенты видят чужие данные)                    |
|                        | - Некачественные данные (дублирование записей, некорректные контакты)                          |
| **Секретные данные**   | - Утечка данных (компрометация API-ключей, доступ к финансовым данным)                         |
|                        | - Потеря данных (отсутствие резервных копий критичных данных)                                  |


## 3. Обоснование актуальности рисков

### Публичные данные
- **Искажение данных**
  → Клиенты могут принимать решения на основе неверной информации, что ведёт к репутационным потерям.

- **Обесценивание данных**
  → Устаревшие данные снижают доверие к сервисам компании.

### Внутренние данные
- **Утечка данных**
  → Конкуренты могут получить доступ к стратегическим отчётам.

- **Потеря данных**
  → Отсутствие документации усложняет поддержку систем.

### Конфиденциальные данные
- **Утечка данных**
  → Нарушение закона о персональных данных (152-ФЗ), репутационные потери (как у конкурентов).

- **Искажение данных**
  → Клиенты видят чужие данные в ЛК (текущая проблема PropDevelopment).

- **Некачественные данные**
  → Ошибки в CRM усложняют работу с клиентами.

### Секретные данные
- **Утечка данных**
  → Финансовые потери (мошенничество с банковскими данными), компрометация интеграций с госорганами.

- **Потеря данных**
  → Невозможность восстановить доступ к ключевым системам.


## 4. Оценка рисков

| Риск                           | Категория данных       | Оценка       | Обоснование                                                                 |
|--------------------------------|------------------------|--------------|-----------------------------------------------------------------------------|
| Утечка персональных данных     | Конфиденциальные       | Критический  | Нарушение 152-ФЗ, репутационный ущерб, штрафы.                             |
| Искажение данных в CRM         | Конфиденциальные       | Значительный | Жалобы клиентов, снижение доверия.                                         |
| Утечка API-ключей              | Секретные              | Критический  | Возможность несанкционированного доступа к данным партнёров и клиентов.    |
| Потеря внутренних отчётов      | Внутренние             | Значительный | Замедление процессов принятия решений.                                     |
| Искажение публичных данных     | Публичные              | Незначительный | Можно быстро исправить, но влияет на UX.                                  |
